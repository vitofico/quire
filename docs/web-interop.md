# Web and Android reader interoperability

The release-APK exercise uses Quire Android `v2026.11.22.346` on disposable
`emulator-5582`, the public APK verified against its published SHA-256,
and an isolated native-auth Quire candidate with disposable Postgres.
No existing accounts or deployments are involved. The fixture is generated by
`python3 scripts/make-reader-pause-fixture.py /tmp/reader-pause.epub`.
It contains original text, three spine resources, and recurring passages with
numbered markers to distinguish occurrences.

The signed APK enforces HTTPS even for an ADB-reversed localhost URL. Serve
the candidate over HTTPS with a short-lived fixture CA trusted by the disposable
Android profile. Browser tests may use the same fixture endpoint with the
fixture certificate trusted for that browser session.

Record the selected passage's chapter and numbered paragraph on each client,
the saved locator and the exact verified DOM range. A library listing, copied
quote, or a chapter-level jump alone is insufficient to demonstrate exact
passage restoration. A web-created comment must appear in the Android UI.

## Observed signed-release round trip

The browser used the packaged Chromium client served by the same candidate
and a fresh native browser session. The original EPUB was selected locally
on both clients. The Android import appeared on the browser shelf before the
browser had the file, and the matching browser import reused the mirrored
identity. The browser generated sync requests for metadata, progress and
highlights. No server book-content route was used.

| Direction | Result |
| --- | --- |
| Android → web highlight | The signed APK selected `Mira` in Marker 1-17, amid 60 occurrences of the same word. Its v3 anchor points to `EPUB/part1.xhtml`, DOM path `[17,0]`, offsets 13–17. Chromium's **Go to passage** resolved exactly that DOM range through the CSS highlight registry and displayed the Android comment. |
| Web → Android highlight | Chromium selected `Mira walked beside the quiet river` in Marker 1-37. Quire Server persisted the browser comment and v3 anchor at `[37,0]`, offsets 13–47. The signed APK pulled both, displayed the comment, and tapping the quote painted just that occurrence on the page with Marker 1-37. The neighbouring identical quotations were unpainted. |
| Android → web progress | The release APK wrote a chapter progression of 0.2308021085624733 and no exact viewport anchor. Android showed Marker 1-15 through 1-19. Chromium showed Marker 1-13 through 1-15 and labelled this as an approximate restore. Exact Android → web progress for this release remains unqualified. |
| Web → Android progress | Chromium moved to Part 2 and saved a v3 reading position in Marker 2-03. The same marker remained visible after increasing the font size. Android reopened Part 2 on a page containing Marker 2-03 with Marker 2-01 at its beginning. This confirms the saved paragraph was visible. The signed APK's internal viewport offset was not inspected. |
| Changed chapter | Chromium, WebKit and Linux Firefox resolved the actual release-APK fixture on the original chapter and rejected its old anchor after an earlier paragraph changed. All 60 copies of the quotation still existed. The quotation and comment remained available from the captured record. |

The captured release input is in
[`web/e2e/fixtures/android-v2026.11.22.346.json`](../web/e2e/fixtures/android-v2026.11.22.346.json).
The test named **verifies an APK-recorded repeated passage and refuses the
changed edition** in [`web/e2e/reader.spec.ts`](../web/e2e/reader.spec.ts)
recreates the EPUB and verifies the exact range and rejection. The existing
reader adapter test covers a longer chapter and selection across inline markup.
A signed release with the newer Android viewport capture still needs its own
exact progress round trip. Actual mobile Safari and screen-reader qualification
are outside this emulator exercise.
