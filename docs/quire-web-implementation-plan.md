# Quire Web implementation plan

**Proposed 23 November 2026.** Baseline is Quire main at `8c965363658b`. Deliver a complete browser edition inside the existing Quire Server image. A reader can start on Android, resume at the same passage on a laptop, annotate offline, and return to the annotation on Android. Someone who only uses a browser can also build and read their own library.

## Implementation record

The browser edition uses a sandboxed XHTML renderer over local EPUB files. The client and Android share Quire’s structural locator contract. Native browser sessions require an explicitly enabled Quire-only HTTPS origin, and the shared Calibre-Web origin supports the Basic-auth topology. The server includes a progress-branch migration for idempotent library uploads. ## What ships

| Surface | What the reader can do |
| --- | --- |
| Library and book details | Continue reading, browse covers or a compact shelf, search, sort, filter by status or local availability, follow a series, inspect metadata, mark finished or abandoned, and resume reading. Distinguish the copy on this browser from membership in the synced library. |
| Bring your books | Import one or more DRM-free EPUBs using a picker or drag and drop. Browse, search, page through and acquire books from an OPDS 1.x catalog. Open a matching local copy of a book already on the shelf, keep it offline and remove its download independently. |
| Reader | Read with keyboard, pointer or touch. Use chapter navigation, table of contents, position control, links and back navigation. Change font, size, spacing, margins and page palette independently of the app theme. Restore place after resize, refresh or fullscreen. Include in-book find with next/previous results. |
| Passages | Select, copy with attribution, highlight, comment, recolour, clear a comment and delete. Browse passages in reading order within a book and search across the current account's saved quotes and comments. Jump to a verified range or read the saved quotation when the edition is unavailable. |
| Pause and return | Save one private memory bookmark per local book and account, edit its note, replace its position, jump back or remove it. Show the approximate distance to the next mapped break where available. Keep bookmarks and their context in the browser. |
| Discovery and insights | Show library stats, ISBN lookup, already-owned matches and deterministic affinity. Offer camera scanning where supported and manual ISBN entry everywhere. With explicit AI opt-in, support book and catalog previews, promotion after import, citations and source details, regeneration with feedback, reader profile, discovery suggestions, language, tone and configured provider choice. |
| Settings and accounts | Support browser-local use, catalog-only use and connected Quire accounts. Expose active identity, server capabilities, sync status, offline storage, appearance, UI language, licenses and What's New. Show account export, device/session controls or hosted account management where the deployment supports them. Keep operator settings at the existing admin page. |

Use Quire's Paper, Sage, Ink and Midnight palettes and existing branding. On desktop the shelf, reader and highlights each get a linkable view. Inside a book, the TOC or highlights can occupy a side panel while text keeps a comfortable measure. On narrow screens the panel becomes a dismissible sheet. Keep private text and source credentials out of URLs. Ship English, Spanish, Italian, French and German with the current app terminology. ## Architecture and delivery decisions

- **One distribution.** Add a sibling `web/` package with React, TypeScript, Vite, a pinned pnpm lockfile, Vitest and Playwright. Follow Spunto's build pattern. A Node build stage produces static assets, and the existing Python server serves them under `/quire/`. Both UI and API report the same build revision. Keep Calibre-Web at `/`. Only browser navigation within the app gets the SPA fallback. Missing assets and unknown API routes must still return their proper errors.
- **Two sources of truth.** Quire Server owns synced reading state. The catalog or a user-selected file supplies the EPUB. The browser parses and stores the file and pushes the established metadata. A mirrored book can therefore have progress, highlights and no available bytes. Its primary action is **Read**, **Download from catalog** or **Open your copy**, according to what this browser can actually access. A native account with no catalog can still import and sync. This design also works for a local-only reader. [Quire architecture](architecture.md)
- **Browser storage.** Use IndexedDB for account-scoped metadata, progress, highlights, preferences, cursors, the durable write queue and initially EPUB blobs behind a small storage interface. Keep public versioned application assets in a service-worker cache scoped to `/quire/`. Keep private APIs and authenticated catalog requests out of shared HTTP/service-worker caches. Start with user-requested offline downloads, report storage usage and quota failures, and recover cleanly from browser eviction. A book is marked available offline only after a complete verified write.
- **Account boundaries.** Derive the namespace from server origin, auth backend and verified stable subject. Give local-only and catalog-only collections independent namespaces. Never silently attach a guest shelf to a signed-in account. Offer an explicit copy/import operation. Lock a connected account's offline collection on sign-out and offer a clear-device-data action. Explain that offline access on a remembered personal browser relies on the browser profile. On shared devices default to session-only access and purge private state on sign-out. If unsent changes exist, show their count and offer sync or explicit discard before clearing them.
- **Reader engine decision.** Try Readium Web's TypeScript navigator first. It consumes publication manifests and resources, so the spike must also supply a browser-local EPUB package reader, resource resolver and positions. Treat this as a dependency choice pending evidence. If that combination cannot render locally with isolation and exact interoperable anchors, evaluate a second browser EPUB renderer behind the same small interface before choosing. Record supported layouts, license obligations and bundle size. Quire keeps the identity, locator compatibility and sync logic outside the engine. [Readium Web architecture](https://readium.org/web/)
- **Catalog topology.** Support Calibre-Web on the same origin and external HTTPS catalogs that permit browser requests. Resolve acquisition and cover links against the feed base, handle relative links and pagination, and bind catalog credentials to the configured origin. For separately hosted Calibre-Web installations without CORS, document an operator-configured same-origin reverse-proxy mount to that specific catalog. For an arbitrary external feed that blocks browser access, explain the issue and offer local file import. Keep the server's existing push-based architecture. [Quire deployment guide](../server/README.md)

## Delivery sequence and acceptance gates

### 1. Prove the Android → web → Android reading loop

First deliverable is one reproducible integration experiment. Use a redistributable EPUB with repeated sentences, inline markup, multiple spine resources and a long paragraph. Capture progress and highlight payloads produced by the released Android app. Read them in a real browser from a locally chosen EPUB, move forward, change the type size and create a commented highlight. Feed the resulting data back through an actual Quire Server to Android. Record both exact DOM ranges and the visible passage on both clients. Run an edition with a changed chapter as a negative case.

Reuse the versioned `quireDomRange` anchor implementation or extract its pure operations into a shared asset. Verify the document fingerprint, offsets, resource hrefs and text survive ZIP extraction, XHTML parsing and reader decorations. Inspect `quireViewportPosition` and page-start anchors separately from selection ranges. Preserve unknown and legacy locator fields when reading records. Avoid rewriting a precise remote locator with a coarse initial layout event. A chapter-level fallback may be labeled for progress, while a highlight must resolve unambiguously before a jump or decoration.

**Exit gate.** Both clients resume the same passage at different viewport sizes, and each lands on the other's exact highlighted occurrence. A changed chapter preserves the quote and comment with an unavailable-location state. A local import makes zero book-content requests to Quire Server. Produce a fixture set, renderer decision and a short compatibility report before building the rest of the reader. [Android reader implementation](../reader/src/main) · [Highlight behavior](reader-highlights.md)

### 2. Ship the shell, routing and sign-in in a candidate image

Build the responsive shell, code-split the reader, add the five language catalogs, and expose a small versioned bootstrap response that identifies enabled surfaces, supported login flow and public catalog base when configured. Reuse authenticated capabilities where available. Add direct and reference-proxy tests for `/quire`, `/quire/`, a deep link, missing assets and the old paths. The reference Caddy matcher currently omits `/auth/*`. Forward only the public identity paths needed, keeping internal lifecycle and service-token operations private.

| Configuration | Browser behavior |
| --- | --- |
| Native password or OIDC | Use the existing HttpOnly browser session, `/auth/v1/me`, Origin and CSRF checks. Add a server-validated fixed login destination for the reader. The current successful OIDC callback targets `/cloud/account`; preserve it for existing Cloud callers and the separate deletion reauthentication flow. Test logout, expiry and account switching. |
| Calibre-Web Basic | Prompt for credentials over HTTPS, validate through the existing backend, and keep the Basic header in memory for the active session. Prompt again after a reload when online sync requires it. Limit its use to the configured Quire API and explicitly selected matching catalog origin. Verify the canonical account identity before unlocking the sync queue. Document the persistence difference from native sessions. |
| Full or sync-only | Enable the synced shelf, reader, highlights and stats in both. Gate insights by the actual AI configuration, compatible credentials and user consent. |
| AI-only | Offer local reading and explicitly enabled insight operations compatible with the configured AI auth mode. Hide synced library, stats and server-backed highlights. For a deployment with service-only AI credentials, show local reading and explain the unavailable account integration. Never distribute an operator token to the browser. |
| Local or catalog-only | After loading the shell, allow local import and offline reading without signing into Quire. A catalog connection supplies books. The UI shows which changes are stored on this browser. |

**Exit gate.** Sign in as two different users in succession, including two users of the same catalog. Verify that cached books, pending writes, highlights and AI state from the first account cannot appear or replay in the second. Existing Android logins, hosted account callbacks, Calibre-Web, MCP and admin routes pass regression tests. [Server authentication and deployment modes](../server/README.md) · [Reference Caddy configuration](../server/caddy/Caddyfile)

### 3. Build import, catalogs and the shelf

Port the sampled hash and OPF identifier normalization against the shared Kotlin/Python fixtures. Use actual EPUB bytes for `content_hash`, preserve `identity_hash_version`, and use `identity_hash` on the bulk library wire. Extract title, authors, series, language, subjects, ISBN, cover and description locally. Handle a missing identifier, duplicates, malformed files, a different edition with the same identifier, interrupted downloads and quota exhaustion. For conflicts, show a recoverable choice and retain each reader's existing progress.

Implement OPDS navigation, search, feeds, sort controls, details and acquisition. Join the server's paginated library mirror to progress snapshots and browser availability. Use imported metadata to enrich the local view and only push supported fields. A mirrored record has optional `opds_href` and limited metadata, so design a cover fallback and show unknown details honestly. Keep catalog URL, credentials and file access separate from synced identity. Specify reconciliation across paginated reads and concurrent updates; replay or add an additive stable server cursor if the existing listing cannot converge under the test workload.

**Exit gate.** On a fresh laptop, an Android-sideloaded book appears on the shelf before the file is available. Choosing the same file reuses its identity and state. A catalog-backed book downloads and opens. Removing the browser download preserves the synced record and highlights, including after reimport. Explicit removal from the synced library has its own clearly labeled action and respects existing tombstones. [Library wire contract](sync-api.md) · [Identity fixtures](../core/identity/src/test/resources/identity)

### 4. Complete the reader and durable sync

Build navigation, preferences, text search, links and selection on the engine chosen in phase 1. Parse and render publication content inside an isolated context. Block book scripts, external subresources and forms by default, constrain decompression and resource sizes, and isolate the trusted reader bridge from publication markup. Keep book content away from app cookies, APIs and private storage. Verify embedded images, fonts, nested paths and the chapter DOM representation used to calculate anchors. Bundle fonts locally with their notices.

Persist reading changes locally in the same transaction as their queue entries. Flush on resume, reconnect and explicit **Sync now**. Handle multi-tab writes, interruption after the server accepts a request, stale responses, sign-out and expired sessions. Preserve the original operation timestamp on retries. A progress pull returns a full snapshot even with `since`; merge by client timestamp and reconcile the authoritative row on stale push. Keep finished and abandoned state consistent with Android. Visiting the shelf or opening a second tab must never advance or rewind a book by itself.

**Exit gate.** Download a book, disconnect, restart the installed or ordinary browser app, change settings and read another chapter. Reconnect after Android has also written progress. Both clients converge under the server's existing conflict rules. Repeat after a tab crash, storage failure and session expiry. Check layout and navigation for reflowable, RTL and fixed-layout fixtures; document any supported-format limitation explicitly. [Progress and library protocol](sync-api.md)

### 5. Complete highlights, private memory bookmarks and offline recovery

Implement the full passage workflow and cross-book search over the active local replica. Use the existing UUIDs, comments, colours, deletion tombstones and authoritative winners. Apply one pull page and its revision cursor atomically, exhaust `has_more`, and rebuild safely after `highlight_cursor_reset_required` while retaining unacknowledged edits. Preserve omitted-versus-cleared comments for mixed client versions. Show sync state separately from the user's saved text. Keep pause bookmarks, optional note and context local, with explicit return and replace actions and the existing book-removal semantics.

**Exit gate.** Verify creation on each platform, offline comment edits, colour changes, deletion against a stale device, multiple pages of highlights, cursor reset, repeated passages and same-file reimport. A removed download retains quotes. An unresolvable range retains the user's words. Verify via captured requests that pause notes never leave the browser. [Highlight sync fixtures](../server/tests/fixtures/highlight-sync.json) · [Pause and return](reader-pause.md)

### 6. Complete discovery, AI and account settings

Implement library stats and series continuation, ISBN entry/camera flow, OpenLibrary metadata and cover lookup, owned-book detection and deterministic affinity. Show which actions contact an external service. Keep ISBN lookup usable with AI disabled; ask for camera access only when scanning. Build book/catalog insight views and source audit, cached results, preferences, provider selection, profile refresh/deletion and discovery. Reuse the existing insight lookup/promotion, profile and capability contracts. Reuse Android's payload allowlist for each request. Exclude the EPUB file, memory notes and private annotations from provider requests. Handle quota, unavailable provider, unsupported auth mode, cancellation and retries without duplicate paid generation.

Finish account controls against the available public APIs. Preserve the operator's existing recovery or hosted lifecycle flow, and test return navigation from it. Implement storage management, sync diagnostics free of private reading content, theming, translated help, licenses and What's New.

**Exit gate.** Test with AI disabled, enabled before opt-in, enabled after opt-in, budget exhausted and selected provider removed. Generating a preview and later acquiring that same edition reuses its insight according to server identity rules. ISBN affinity makes no model call. A user with no camera can complete lookup, and a sync-only reader can complete the entire reading and annotation workflow. [Quire AI configuration](configuration.md) · [API reference](sync-api.md)

### 7. Package, qualify, release and roll back

Change the server Docker build context from `server/` to the repository root with `server/Dockerfile`, or use explicitly named contexts that supply the same inputs. Update all build invocations, ignore rules and CI path filters for `web/**`, shared fixtures/assets and packaging changes. Keep the final runtime free of Node and build tools introduced solely for the web build. Web-only changes should build and qualify a server image independently of Android's APK release workflow. Preserve the existing server license and notices, and document the chosen web code license and third-party font/renderer notices before distribution.

| Test layer | Evidence required to ship |
| --- | --- |
| Shared contracts | TypeScript, Kotlin and Python agree on identity, legacy/current progress, exact highlight payloads, comments and tombstones using shared fixtures. Existing server and affected Android suites pass. |
| Packaged integration | Start the built image with Postgres and exercise both reference Compose topologies, including the full Caddy + Calibre-Web flow. Verify the mode/auth combinations in phase 2, HTTPS deep links, OIDC destinations, and API error responses. |
| Real reader | Exercise import → offline reload → annotate → reconnect in Chromium, Firefox and WebKit. Confirm touch selection and offline restart on actual mobile Safari and Android Chrome. Complete a release-APK ↔ browser round trip through the candidate image and save locator/visible-passage evidence. |
| Accessibility and language | Complete sign-in, import, read, annotate and return by keyboard and with a screen reader. Check zoom, contrast, reduced motion, focus across the reader frame and panels, all five languages and RTL book navigation. |
| Privacy and performance | Independently review reader isolation, auth scope, cache boundaries and tenant switching. Record cold shelf load, time to first chapter, memory for a large EPUB, long-shelf scrolling and highlight search on representative devices. Set regression budgets from phase 1/3 measurements and enforce them before release. |
| Upgrade and rollback | Install the previous image, sync real fixture data, upgrade in place, then exercise an already-open tab and an offline client returning to the new build. Version local storage, queue formats and static caches. Prompt for reload after persisting work. Rehearse disabling the web mount and reverting to the prior image digest with Android sync intact. Any database change needs a separately verified backward-compatible migration. |

**Rollout.** Produce a commit-pinned candidate for an opt-in self-hosted pilot after phase 5. Qualify phases 6–7 before enabling the full edition by default. Update installation, reverse-proxy, offline storage, browser support, privacy, release and troubleshooting docs. Call the release complete when a fresh install, an upgrade and the two-device round trip all succeed using the distributable image. [Server CI](../.github/workflows/server-ci.yaml) · [Release process](release.md)

## Implementation order

Start with the phase 1 fixture and renderer experiment. Packaging/auth and library/import can proceed alongside reader implementation once identity and locator contracts are pinned. Highlights depend on the durable queue and the verified range adapter. Stats and ISBN work can proceed once the shelf model exists. AI depends on capability-aware authentication; final rollout depends on every acceptance gate above. Size the remaining work after the renderer and authenticated catalog experiments, which carry the most uncertainty.
