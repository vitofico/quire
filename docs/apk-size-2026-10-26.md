# Release APK size validation — 2026-10-26

Enabled R8 code optimization and resource shrinking for release builds, using
Android's optimized defaults and dependency consumer rules. Debug builds keep
their existing behavior. No app features, reader fonts or translations were
removed manually, and no dependency versions changed.

## Measurement

Both unsigned APKs use the same frozen Android working tree, including its
existing uncommitted changes, based on commit
`5ed3839819faefd19898a8a5f4250055a9a983b8`.
Only the release build settings differ: optimization and the reproducibility
safeguards described below.
The Docker image, Gradle, SDK and dependency graph are unchanged.

| Measure | Before | After |
| --- | ---: | ---: |
| APK bytes | 28,366,323 | 8,924,347 |
| APK size, decimal MB | 28.37 | 8.92 |
| Compressed DEX bytes | 21,910,677 | 3,407,069 |
| Compressed font bytes | 3,001,658 | 3,001,658 |
| DEX class definitions | 49,107 | 8,290 |

The APK is **68.54% smaller**, saving
19,441,976 bytes. All 15 packaged font files retain identical
paths and SHA-256 hashes. The checked-in license JSON also retains identical
bytes in the optimized APK (`res/M7.json`). No custom keep rules or blanket
warning suppression were needed.

An initial cached-versus-clean comparison differed in DEX and baseline profile.
The difference was traced to six cached incremental Compose class files. Three
full compilations produced identical output across all 789 compiler output
files. Release UI compilation now sets `incremental = false`, which also gives
it a separate build-cache key; debug compilation remains incremental.

DEX and mapping then matched, leaving only nondeterministic `baseline.prof`.
Release ArtProfile tasks are disabled following
[F-Droid’s documented workaround](https://f-droid.org/docs/Reproducible_Builds/#bug-baselineprof-not-deterministic).
Clean release assembly removes old profile outputs. The tradeoff is omitting
bundled runtime baseline profiles (prepackaged startup-optimization hints);
no startup performance benchmark is claimed. Debug tasks are unchanged.

## Validation

- Baseline and optimized `:app:assembleRelease`: pass.
- `test lint assembleDebug`: pass; 1,390 test executions across
  170 suites, zero failures/errors/skips. These include debug, release
  and JVM module variants. Lint reports contain zero errors and 121 warnings.
- Release-tooling Python tests: 15 pass.
- File hygiene and secret checks: pass in an isolated Git snapshot using the
  same files, hook configuration and secret baseline. The original checkout's
  hook invocation stops because its pre-existing `.secrets.baseline` is
  unstaged; its staging state was preserved.
- Android 36 emulator: fresh HTTPS Basic login, catalog parsing, EPUB download,
  library upload and batch sync, progress push/pull, EPUB rendering, page
  navigation and saved-position persistence pass against a local fixture server.
- Upgrade checks cover the unoptimized to initial optimized APK, and the initial
  optimized to final APK: documents, progress and sync state are unchanged before
  first launch. The optimized reader restores the saved
  chapter position (`0.0666748981355723`).
- CameraX preview and analysis use cases start and produce emulated frames,
  with no camera initialization errors after enabling both advertised cameras.
  The initial missing-camera warning also occurred with the baseline APK.
- No fatal Android runtime exceptions were observed in the optimized smoke run.
- Two clean release builds with `--no-build-cache --offline`: pass, byte-identical.
  The affected app release unit tests and release lint were rerun successfully
  after the build safeguards.
- Final profile-free APK: fresh login/download, upgrade-state preservation,
  reader restoration/page navigation and live emulated camera preview pass;
  no fatal runtime exceptions.

CI now builds the optimized release before pushing its release tag, and the
normal release job retains `mapping.txt` as an artifact for stack-trace retracing.
